# ASL Finger-Spelling Translator

A real-time American Sign Language (ASL) alphabet recognition system that translates hand gestures into text using computer vision and machine learning. Built with MediaPipe for hand landmark detection, a windowed feature classifier for letter recognition, and Claude AI for sentence completion.

## What It Does

This project implements a real-time ASL finger-spelling translator that lets a user sign letters from the American Sign Language alphabet in front of a webcam and watch them appear as text on screen. The system uses MediaPipe to detect 21 hand landmarks per frame, extracts 115 engineered features per frame combining static hand pose geometry with motion statistics computed over a rolling 15-frame window, and classifies the result using a trained SVM or KNN classifier. Motion letters like J and Z — which are defined by a path traced in the air rather than a static pose — are distinguished from their look-alikes (I and S) using the motion feature component, with no hardcoded rules. Once a word is spelled, the Claude API generates a sentence completion suggestion. The system ships with two GUIs: a clean translator interface for end users, and a training studio for data collection, model training, and analysis.

## Quick Start

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Open the Training Studio

```bash
python training_gui.py
```

On first launch, a dialog will ask whether you want to load pre-collected training data or start from scratch:

- **Use pre-collected data** — loads the bundled dataset (~400 samples per letter) so you can skip straight to training. You can still add your own data on top.
- **Start from scratch** — collect your own samples via webcam from the Collect tab.

### 3. Train the model

In the **Train** tab, select SVM and click **Start Training**. Takes 30–60 seconds.

### 4. Run the translator

```bash
python translator_gui.py
```

Or use the CLI version:
```bash
python app.py
```

**Controls:** Hold a letter sign steady → the progress bar fills → the letter is added to the word. Press Space to confirm a word and trigger an AI suggestion, Enter to accept the suggestion, Backspace to delete, C to clear.

## Evaluation

Results after training on ~400 samples per letter (26 letters, ~10,400 total samples) with a windowed SVM classifier:

| Metric | Score |
|---|---|
| Overall accuracy | ~99% |
| Macro F1 | ~99% |
| Macro Precision | ~99% |
| Macro Recall | ~99% |
| 5-fold CV accuracy | ~99% ± 0.1% |
| Inference time | < 2ms per frame |
| Real-time throughput | 30+ fps |

Confusion cases are concentrated in geometrically similar letter pairs (A/E/S, M/N/T). The windowed motion features reduce I/J confusion to near-zero — the classifier learns the distinction from motion statistics alone, without any hardcoded routing logic.

See `results/` for full confusion matrices, per-class breakdowns, hyperparameter tuning curves, and error analysis plots generated by `src/analysis.py`.

## Technical Details

### Feature Engineering (115 features per frame)

**Static pose features (85):**
- 63 normalized landmark coordinates — 21 hand joints × (x, y, z), translated to wrist origin, scale-normalized so max distance from wrist = 1
- 5 finger curl angles — sum of joint bend angles per finger, capturing open vs. curled state
- 10 pairwise fingertip distances — all C(5,2) pairs, capturing spread and clustering
- 4 thumb-relative features — thumb-to-index PIP, thumb-to-pinky MCP, vertical position relative to index MCP, extension ratio
- 3 palm orientation components — unit normal vector to the palm plane

**Motion features (30):**

Computed over a rolling 15-frame window (~0.5 sec). For each of 5 fingertips: mean velocity magnitude, max velocity magnitude, total path length, net displacement magnitude, and displacement direction (x, y). For static letters these values are near-zero. For J and Z, the pinky and index fingertips respectively show pronounced motion with distinct directional profiles.

### Why Windowed Features Fix I/J Confusion

I and J are identical in static pose — both are a raised pinky with a slightly bent tip. A per-frame classifier cannot distinguish them. By including motion statistics over the past 0.5 seconds, the classifier sees that I has near-zero motion features and J has high pinky velocity and a curved path. No hardcoded logic is needed — the model learns this distinction directly from the training data.

### System Architecture

```
Webcam → MediaPipe → WindowedFeatureExtractor → Classifier → LetterAcceptor → WordBuilder → GUI
```

The `WindowedFeatureExtractor` is the same class used at training time and inference time, ensuring the feature distribution matches exactly. The `LetterAcceptor` requires a prediction to hold steady for 20 consecutive frames with a 0.8-second cooldown, preventing rapid false triggers during natural hand movement.

### AI Sentence Completion

When the user presses Space to confirm a word, the current text is sent to the Claude API (`claude-sonnet-4-20250514`) which returns a short natural completion suggestion. The user can accept it with Enter or ignore it and keep spelling. API key setup is documented in `src/api_config.py` and `SETUP.md`.

## Limitations

- Trained on a single user's hand — accuracy varies with different hand sizes and skin tones
- Performance degrades in poor lighting conditions
- Only the ASL finger-spelling alphabet is supported (no full ASL words or two-handed signs)
- The 15-frame warmup period means predictions are delayed ~0.5 sec when a hand first enters the frame
